# Implement the Cache-Write Counts in `Usage`

Associated MADR: [0036-MADR-cache-write-token-count.md](0036-MADR-cache-write-token-count.md)

## Goal

When it is done:

* `llmprovider.Usage` has `CacheWriteTokens` and `CacheWrite1hTokens`
  (0036-MADR D1), each a part of the count before it:
  `CachedTokens + CacheWriteTokens <= InputTokens`, and
  `CacheWrite1hTokens <= CacheWriteTokens`.
* Each wire decodes them as D2 gives:
  * Messages from `cache_creation_input_tokens` and
    `cache_creation.ephemeral_1h_input_tokens`, in a body and in a stream;
  * Responses from `input_tokens_details.cache_write_tokens`;
  * Chat Completions from `prompt_tokens_details.cache_write_tokens`;
  * generateContent and Interactions leave both at zero.
* `api-standards.md` R7 and `llmtest`'s R7 check hold the new rules (D3).
* Every canned reply that can report a write reports one, and each
  provider's decoded `Usage` is checked against it.
* A live measurement, run before the decoders change, shows what each
  service sends. A second run, after the change, shows the decoded counts
  match it.
* `v1.10.0` is released, and only grows the API: two fields.

No existing count changes meaning. No request changes: nothing here asks a
service to cache (D4).

## Scope

### In scope

* **The type:** `llmprovider/contract.go` (`Usage`).
* **The decoders:**
  * `llmprovider/internal/wire/messages/messages.go`: `usage`,
    `usage.counts`, and the stream's merge in `Events`;
  * `llmprovider/internal/wire/responses/responses.go`: `usage`;
  * `llmprovider/internal/wire/chatcompletions/chatcompletions.go`: `usage`.
* **The checks:**
  * `llmprovider/llmtest/llmtest.go` (`checkResponse`'s R7 block) and
    `llmtest_test.go`;
  * `llmprovider/internal/wirecase/wirecase.go`: the canned replies, the
    expected `Usage` values and `usageFor`.
* **Tests:**
  * `usage_test.go` in `messages`, `responses`, `chatcompletions`,
    `generatecontent` and `providers/gemini`;
  * a new live measurement, `llmprovider/live_0036_cache_write_measure_test.go`.
* **Docs:**
  * `docs/guides/api-standards.md` R7;
  * `docs/architecture.md`, the `Response.Usage` paragraph;
  * `README.md` Status, and this PLAN's release notes;
  * `docs/README.md`'s index.

### Out of scope

As 0036-MADR D4 decides:

* any request field that asks for caching: `cache_control`,
  `prompt_cache_retention`, `prompt_cache_options`;
* a cost helper, and a 1-hour price in `ModelRates`;
* gobble-cli's adapter, and its double count of cache reads, which belong
  to that repository;
* `docs/guides/migrating-from-mcplib.md`: `Usage` has no `mcplib`
  ancestor, so it gains no row.

## Rollout and Rollback

* **Rollout:** the records, then one commit per phase, then `v1.10.0`.
  Phase 1 changes no module code. Phase 2 adds the fields, which stay zero
  until Phase 3. Each commit keeps every check green.
* **Compatibility:** two exported fields are added to a struct. apidiff,
  which `make api-check` runs against the latest v1 tag (R48), reports an
  added field as compatible. A caller that writes a `Usage` literal without
  field names would no longer compile. No such literal exists in this
  repository. A caller comparing a whole `Usage` sees new values only where
  a service reports writes.
* **Rollback:** Phase 3 reverts alone, and the fields read zero again.
  Phase 2 reverts with Phase 3 before a release. After `v1.10.0`, a field
  cannot be removed in v1 (R48), so a fault is fixed forward in a patch
  release.

#### Release notes: `v1.10.0`

`v1.10.0` reports cache writes in `Usage` (0036-MADR, and its amendment of
2026-10-12). The exported API only grows: two fields.

**`Usage.CacheWriteTokens`** is the part of `InputTokens` written to the
service's cache. It does not overlap `CachedTokens`, the part read from it,
so `InputTokens - CachedTokens - CacheWriteTokens` is the uncached input.

**`Usage.CacheWrite1hTokens`** is the part of the writes with a one-hour
lifetime. Only Anthropic reports it.

**Where they come from:**

| Wire | Write count |
| :--- | :--- |
| Anthropic Messages (Claude, OpenCode Zen's Claude route) | `cache_creation_input_tokens`; the 1-hour part from `cache_creation` |
| OpenAI Responses (OpenAI, ChatGPT, Grok, Zen's OpenAI route) | `input_tokens_details.cache_write_tokens` |
| Chat Completions (Kilo, Together, Hugging Face, Ollama, Zen's chat route) | `prompt_tokens_details.cache_write_tokens`, else Kilo's top-level `cache_creation_input_tokens` |
| Gemini `generateContent` and Interactions | none: both stay zero |

**Measured on 2026-10-12:**

* OpenAI's `gpt-6-luna` writes on its own, and from GPT-5.6 a write costs
  1.25 times the input price;
* Kilo caches OpenAI and Claude models on its own;
* Claude, called directly or through Zen, writes only when the request asks
  for caching, which this SDK does not yet send;
* xAI and DeepSeek report no write.

**Pricing a response** takes `catalog.ModelRates` (`v1.9.0`):

* uncached input at `Input`;
* `CachedTokens` at `CacheRead`;
* the 5-minute writes, `CacheWriteTokens - CacheWrite1hTokens`, at
  `CacheWrite`;
* the 1-hour writes at twice `Input`, Anthropic's price.

The SDK publishes the counts, not a cost (0033-MADR Q12).

**`llmtest`** now refuses a negative write count, reads and writes above the
input, and 1-hour writes above the writes.

**Upgrading:** no code change is needed. A caller that writes a `Usage`
literal without field names must name them.
